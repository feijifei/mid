# 平台架构与策略接入

## 决策

第一版采用模块化单体。研究、回测、模拟交易共享策略接口和领域对象；外部数据与券商连接通过适配器替换。SQLite 与内部模拟成交是本地实现，后续可分别替换为 PostgreSQL 和正式券商适配器。

开源调研选择 vn.py 作为下一阶段交易基础设施首选，但不让用户策略继承 vn.py 模板类。`0.1` 先用轻量本地实现验证领域接口与完整交互；`0.2` 在相同接缝下增加 `VnPyBacktestAdapter` 和 `VnPyPaperBrokerAdapter`，以替换而不是叠加两套运行逻辑。

## 策略接缝

策略模块的完整接口只有元数据和 `generate(context)`。平台保证输入行情不会晚于 `as_of`，策略保证输出非负、有限且总和不超过 1 的目标权重。策略不得操作数据库、网络或订单。

```text
MarketDataSource -> StrategyContext -> Strategy.generate
                                      |
                                      v
                              TargetPortfolio
                                      |
              PortfolioPlanner -> RiskEngine -> Broker Adapter
```

此处存在两个真实适配器方向：演示/CSV行情，以及内部模拟/未来外部券商。测试通过同一个接口观察结果，不穿透到模块内部状态。

## 生产化缺口

- 插件目前是受信任代码并与平台同进程；生产版本应隔离运行并校验制品哈希。
- 模拟成交目前立即全额成交；后续需增加部分成交、撤单、未知状态和重连恢复。
- SQLite适合课程原型；多用户生产环境应替换为PostgreSQL。
- 演示行情仅用于离线验收，不能用于投资结论。
- 外部模拟盘适配器必须在核实接口授权、稳定性和使用条款后实现。
